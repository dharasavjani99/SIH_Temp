# ResQTech — backend

Disaster intelligence API for **Smart India Hackathon 2026, Problem Statement 206**.

FastAPI + PostgreSQL + scikit-learn. This repository holds the server side: the
database schema, the REST API, the risk model and its training pipeline, the
image-analysis service, the routing solver, the chatbot service and the seed
dataset. The React frontend lives separately and talks to this over HTTP.

---

## What is real and what is not

This matters more than any feature list, so it is first.

| Component | Status |
|---|---|
| Risk model | **Trained.** Four `HistGradientBoostingClassifier` models with isotonic calibration, fitted by `scripts/train_risk_model.py`. Out-of-fold AUC and Brier scores are written to `app/ml/artifacts/metrics.json`. |
| Training labels | **Synthetic.** Generated by `scripts/generate_training_data.py` from a physically motivated process. They are *not* observed disaster records. See the warning below. |
| Route optimisation | **Real.** Dijkstra over the road graph in the database, with live condition penalties. |
| Impact segmentation | **Real classical CV.** Per-pixel colour response plus a Sobel gradient pass. A trained U-Net slots in behind the same interface when a checkpoint exists. |
| Allocation engine | **Real.** Demand from planning factors, capped by actual stock, shortfalls reported. |
| Chatbot | **Real, two-mode.** Calls an LLM when a key is configured; otherwise a deterministic retrieval answer over the same database. The response always says which one answered. |
| External feeds (IMD, CWC, Bhuvan) | **Adapters only.** No credentials, so they replay the seeded CSVs and every record is flagged `is_live=false`. |
| Prediction accuracy figure | **Not reported.** There is no validated backtest, so `/api/reports` returns `prediction_accuracy: null` with an explanation instead of a number. |

> **Do not quote the model metrics as forecasting accuracy.** The labels are
> synthetic, so the scores measure how well the model recovers its own
> generator. Retrain on real IMD rainfall, CWC gauge series and NDMA/EM-DAT
> event records before making any claim. The column schema in
> `data/historical_events.csv` is the join target for that real data, so no
> code changes when you swap it.

## Quick start

### Without Docker (SQLite, nothing else to install)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

export DATABASE_URL="sqlite:///./resqtech.db"
python scripts/generate_training_data.py   # writes data/historical_events.csv
python scripts/train_risk_model.py         # writes app/ml/artifacts/
python scripts/seed_db.py                  # loads data/*.csv
uvicorn app.main:app --reload --port 8000
```

Open <http://localhost:8000/docs>.

### With Docker (PostgreSQL)

```bash
docker compose up --build
```

### Tests

```bash
pytest -q          # 21 tests
```

They cover the engines rather than just the plumbing: that more rainfall raises
flood risk, that slope drives landslide risk and not flood risk, that the safe
route really does avoid the landslide-blocked link, that a boat and an ambulance
treat a flooded road differently, that a `public` role cannot call the
prediction endpoint, and that the report endpoint refuses to invent an accuracy
figure.

## How the risk engine works

1. `app/ml/features.py` normalises raw observations into eleven bounded
   features. One module defines the order, so training and inference can never
   disagree about it.
2. `app/services/risk_engine.py` asks `ModelRegistry` for the trained models.
   If the artifact is missing it falls back to the logistic surrogate and says
   so in `model_name` — it never passes off a surrogate score as a trained one.
3. Per-feature log-odds contributions always come from the surrogate, which is
   the interpretable twin of the ensemble. The response labels this
   `explanation_source` so the UI does not overclaim that it is explaining the
   trees themselves.
4. Confidence is derived, not decorative: from the out-of-fold Brier score and
   the distance of the probability from the decision boundary.

## Security

- No secret is in source. Everything comes from the environment; `.env` is git-ignored.
- The LLM key is used server-side only and is never included in a response.
- CORS is restricted to configured origins, never `*`.
- Passwords are bcrypt-hashed at 12 rounds; login returns the same message for a
  bad email and a bad password.
- Every endpoint is typed with Pydantic, so input is validated before it reaches
  a query; SQLAlchemy parameterises all SQL.
- Uploads are limited to PNG/JPEG/WebP under 12 MB and are decoded in-memory.
- The global exception handler logs the traceback and returns a generic message.

## Roadmap

- Replace `data/historical_events.csv` with real IMD/CWC/NDMA series and retrain.
- Train the U-Net on xBD or Sentinel-1 flood masks and drop the checkpoint at `SEG_MODEL_PATH`.
- PostGIS geometry columns and spatial indexes in place of float lat/lon.
- Alembic migrations (currently `create_all` at startup, fine for a prototype).
- Celery beat job to poll the adapters instead of reading seeded observations.
